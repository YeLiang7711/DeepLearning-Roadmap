# LearnSpace Vault 笔记编写规则

本 skill 定义了 LearnSpace（Obsidian 深度学习学习笔记库）的内容编写规范。所有规则都是从用户反复纠正中提炼的——**违反这些规则 = 重写**。

先阅读 `references/writing-rules.md`（文字规则与示例）和 `references/viz-rules.md`（图片规则与模板），再动手。

---

## 总原则

> 用户是深度学习初学者，目标是"建立可迁移的知识体系"，不被温度异常检测单一项目带偏。笔记要让他**真的看懂**，而不是堆砌正确但陌生的术语。

三条最高优先级：

1. **具体例子先行，公式在后**——"先忘掉公式，看一个例子"，公式出现时说"回头看就清楚了"
2. **每个概念必须回答"在深度学习中用在哪"**——但不能被温度项目带偏，保持通用性
3. **原理与应用分层**——数学/原理章节不放应用细节（PaDiM、PatchCore 等），应用放到对应章节，用 `[[wikilinks]]` 连接

## 文字规则速查

### 结构（每节文件）

```
**本节内容**：一句话简述（说明内容讲什么，不重复文件名——Obsidian 已显示文件名，正文首行不要再放 # 标题）

> 属于：[[0-概述-章名|章名]] > X.X.N
> 掌握程度：**会用**（或 了解/深入）

---
（正文：例子 → 直觉 → 公式 → DL 应用）
---
## 总结          ← 每节必须有：对比表或速查表 + 加粗一句话总结
---
- ← [[上一节|上一节标题]]
- → [[下一节|下一节标题]]
```

### 写作顺序（每节内的固定叙事弧）

```
1. 具体问题/场景（带数字的例子，如"测了5次温度"）
2. 直观理解（类比/画面/ASCII 草图，但终稿 ASCII 转 Python 图）
3. 公式（给关键公式，不推演证明；公式前说"回头看就清楚了"）
4. 在深度学习中的应用（至少一个具体落点）
5. 总结表 + 一句话总结（加粗）
```

### 表达要点

- **终端兼容**：解释性句子中的变量名用纯文本（"P(A|B) 叫似然"），不要写成 `$A$`——终端会吞掉 `$...$` 导致句子缺字。公式块 `$$...$$` 保留（Obsidian 渲染）
- **表格内 LaTeX 竖线**：绝对值用 `\lvert \rvert`，范数用 `\|`，条件概率用 `\mid`——裸 `|` 会被 markdown 表格解析器当分隔符吞掉
- **术语首次出现给中文全称**：高斯分布 = 正态分布；Mahalanobis 距离 = 马氏距离；SVD = 奇异值分解
- **符号说明**：第一次出现的符号给出含义（"· 就是普通乘法"、"| 读作给定"）
- **对比优先用表格**：MLE vs MAP、MSE vs MAE、PCA vs PLSR——两列对比表是默认形式
- **一句话总结必须加粗**：每节结尾提炼成一句可记住的话
- **专业度分层**：INDEX.md 中的描述用专业术语（"特征分解、奇异值分解、低秩近似"），笔记正文可以用通俗类比——导航要专业，正文要易懂
- **不堆砌**：用户说过"不需要太纠结于数学原理"和"不能完全专业知识都没有"——公式给关键的，直觉给充分的，证明不展开

### 链接规则

- 相关概念必须用 `[[wikilinks]]` 互链（MSE 跳转到 1.2.4 的导数表、MLE/MAP 章节互链）
- 章节文件用相对路径链接：`[[../1.2-微积分/1.2.4 常见函数的导数|显示名]]`
- 原理章节指向应用章节用 `[[../../11-异常检测基础/...]]` 形式
- 用户提问中出现的、原文没有的内容，整理后**添加到对应笔记**（用户明确要求过）

## 图片规则速查

完整规则和代码模板见 `references/viz-rules.md`。核心：

```
viz/
├── scripts/        ← 脚本，命名：X.X.N-序号_描述.py
└── images/         ← 输出，命名：X.X.N-序号_描述.png（与脚本同名）
```

1. **所有 ASCII 示意图必须转成 Python 图**——用户明确要求过
2. **编号**：`章节号-章节内序号`，如 `1.3.3-1` = 1.3.3 节第 1 张图
3. **中文字体**：`plt.rcParams['font.family'] = 'Microsoft YaHei'` + `axes.unicode_minus = False`
4. **md 引用格式**：
   ```markdown
   ![图X.X.N-N：描述](../../viz/images/X.X.N-N_desc.png)
   *图 X.X.N-N：图注——解释图中每个元素的意义*
   ```
5. **图要讲故事**：模拟数据必须验证数值合理（如 ROC 的 AUC 对照理论值），不能画一个"形状对"但数值错的图
6. **常见坑**（踩过的，不要重犯）：
   - 直方图 `set_ylim` 手写死会裁剪柱子——从 `counts.max()` 取
   - 标注位置用 `axes fraction` 坐标，别用写死的数据坐标
   - ROC 等曲线注意遍历顺序（阈值从小到大 TPR/FPR 从 1 降 0，需反转）
   - matplotlib 3D 曲面效果差——用 plotly 或 pyvista
   - 中文缺字体报 Glyph 警告——检查是否忘了 Microsoft YaHei
7. **图注斜体**：每张图必须有斜体图注，解释图中元素（数据、线条、区域各是什么）

## 编写流程

写任何章节时：

1. 先读 `00-概览/深度学习完整学习路线.md` 对应章节的原始要求（知识点清单、掌握程度）
2. 建目录 `X.X-名称/`，先写 `0-概述-名称.md`（速查表 + 阅读顺序 + 章节链接）。**概述文件名必须带部分名**（如 `0-概述-线性代数.md`），避免 Obsidian 中多个 `0-概述` 重名歧义
3. 按路线图知识点逐节写文件，一节一个文件
4. 需要示意图的，写 `viz/scripts/` 脚本并生成图片
5. 更新 `00-概览/INDEX.md`：📂/📄 前缀 + `[[wikilinks]]` + 专业描述
6. 检查：例子具体吗？公式有吗？DL 落点有吗？总结表 + 一句话有吗？wikilinks 通吗？

## 重写/优化现有内容时

用户说"看不懂/没看懂/优化表达"时，几乎总是同一个问题：**从定义出发而不是从例子出发**。重写策略：

```
旧（看不懂）：定义 → 公式 → 分类 → 应用
新（看得懂）：带数字的具体问题 → 一步一步算出来 → 从算账过程提炼公式 → 术语对照回例子 → DL 应用
```

参考 1.3.2（贝叶斯用检测阳性例子重写）、1.3.4（MLE/MAP 用温度传感器例子重写）——这两节是重写的标准范例。

## 不得违反

- ❌ 章节文件里写 PaDiM/PatchCore 等应用细节（除非是该应用章节本身）
- ❌ INDEX 描述用通俗类比（要专业）
- ❌ ASCII 图留在终稿（必须转 Python 图）
- ❌ 解释性句子用 `$变量$` 行内公式（终端缺字）
- ❌ 表格内裸 `|`（被解析器吞掉）
- ❌ 写了笔记不更新 INDEX
- ❌ 概念不给出 DL 落点

## 提交规范（私人仓库）

- commit message 用简洁一句话（如"添加 1.3 概率统计章节"），**不要加 `Co-Authored-By: Claude` 签名行**（用户明确要求，见记忆 git-commit-style）
- 提交前复查：链接、图片引用、ASCII 残留、编号一致性
