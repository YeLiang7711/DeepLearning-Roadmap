## Git：代码的时光机

### 为什么需要

```
❌ 没有 Git 的日子：
    train_final.py
    train_final_v2.py
    train_final_v2_真的最终版.py
    train_final_v2_真的最终版_改一下.py

✅ 有 Git 的日子：
    git commit 一次 = 一个存档点，随时可以回到任何版本
```

### 三个核心命令

```python
git add train.py          # 1. 把文件放进"暂存区"（准备提交）
git commit -m "修复学习率bug"   # 2. 打一个存档点（含说明）
git log                   # 3. 查看历史
```

### 常用工作流

```bash
# 查看状态：哪些文件改了
git status

# 查看改了什么（提交前必查！）
git diff

# 回到上一个存档（改坏了救命）
git checkout -- train.py

# 分支：并行开发新实验，不影响主线
git checkout -b exp_lr_search    # 新建分支
git checkout main                # 切回主线
git merge exp_lr_search          # 合并分支
```

> **提交信息的规范**（路线图 31 章：Git 分支、commit 和代码审查）：一句话说明"改了什么、为什么"——`git log` 就是实验的编年史。

### 深度学习的 Git 实践

- **代码进 Git，数据和模型不进**（太大）——用 `.gitignore` 排除
- **每次实验前 commit 一次**——跑挂了能回到"开始前"
- **配置也进 Git**——config 的 diff 就是实验差异的记录

```
.gitignore 示例：
data/
runs/
*.pth
__pycache__/
```

## 环境管理：让代码在哪都能跑

### 问题

代码依赖的包版本不一致 → 换台机器就跑不了（或结果不一样）。

### conda：环境隔离

```bash
# 创建独立环境（每个项目一个，互不干扰）
conda create -n learnspace python=3.11

# 激活 / 退出
conda activate learnspace
conda deactivate

# 安装包
pip install torch numpy pandas
```

> **为什么不用系统 Python 直接装**：项目 A 要 torch 2.0、项目 B 要 torch 1.13——装一起会互相覆盖。**一个项目一个 conda 环境**是标准做法。

### 依赖锁定：环境的"配方表"

```bash
# 导出当前环境的完整依赖清单
pip freeze > requirements.txt

# 换机器/换人时一键重建
pip install -r requirements.txt

# 更严谨：conda 完整环境导出（含包来源）
conda env export > environment.yml
```

**requirements.txt 就是环境的"配方表"**——和配置快照一样，**环境也必须有快照**：

```
# requirements.txt 示例
numpy==1.26.4
torch==2.1.2
pandas==2.2.0
```

> **为什么锁版本号**：`torch` 和 `torch==2.1.2` 的区别——前者下次装可能是 2.5（结果可能不同），后者永远装同一个。**版本号 = 可复现性**。

## 实验可复现的完整闭环

```
代码 → Git 管理（每次实验前 commit）
配置 → 存进 runs/ 目录（配置快照）
环境 → requirements.txt 锁定
种子 → set_seed(42) 锁死随机性
数据 → 只读，版本记录
```

**换机器复现一次实验的步骤**：

```bash
git clone 项目代码
conda create -n proj python=3.11
pip install -r requirements.txt
python train.py --config runs/exp_001/config.yaml
# 结果应该和原来一致（同环境 + 同种子 + 同配置）
```

> **与 31 章的连接**：这里的手动流程是实验管理的雏形——容器（Docker）把"环境"也装进一个文件里，CI 自动跑测试，都是同一目标的工业化（18-实验管理与MLOps）。

## 总结

| 工具 | 一句话 |
|---|---|
| Git | 代码的时光机：commit 存档、checkout 回滚、分支并行 |
| .gitignore | 数据/模型/输出不进 Git（太大） |
| conda 环境 | 一个项目一个环境，互不干扰 |
| requirements.txt | 环境的配方表：锁版本号 = 可复现 |
| 完整闭环 | Git + 配置快照 + 环境锁定 + 种子 = 可复现实验 |

> Git 和环境管理一句话：**代码有历史（Git）、环境有配方（requirements）、随机有种子**。三者齐了，"换台机器重跑"才不是碰运气。
