## 为什么需要工程规范

深度学习实验的痛点：**跑出好结果后无法复现**。

- "上次用的学习率是多少来着？" → 记不清了
- "这个 0.92 是哪个模型跑的？" → 三个模型混在一个文件里
- "换台机器就报错？" → 依赖版本不一致

工程规范 = **让实验可追踪、可比较、可复现**（路线图 31 章的核心，这里先打基础）。

## 配置文件：参数和代码分离

### 为什么参数不能写死在代码里

```python
# ❌ 参数散落在代码里，改一个参数要翻遍全文
model = ResNet18()
lr = 0.001
batch_size = 32
epochs = 100
```

```python
# ✅ 参数集中在一个 dict，改配置不碰代码
config = {
    "model": "resnet18",
    "lr": 1e-3,
    "batch_size": 32,
    "epochs": 100,
    "seed": 42,
}
model = ResNet18()
optimizer = AdamW(model.parameters(), lr=config["lr"])
```

### 配置驱动实验：一份配置 = 一次实验

```
实验 = 代码 + 配置
     ↑        ↑
  不动     每次改这个
```

```python
# config.py 或 config.yaml —— 实验的"身份证"
config = {
    "model": "resnet18",
    "dataset": "温度场_202607",
    "lr": 1e-3,
    "seed": 42,
    "output_dir": "runs/exp_001",
}
```

### YAML 配置文件（工业标准）

```python
# config.yaml
model: resnet18
lr: 0.001
batch_size: 32
seed: 42

# 读取
import yaml
with open("config.yaml") as f:
    config = yaml.safe_load(f)
```

> **为什么 YAML 比 Python dict 好**：配置和数据分离——非程序员（现场工程师）也能改；可版本对比（git diff 看到底改了什么）。**保存配置 = 保存实验的身份证**。

## 命令行参数：不改文件也能跑实验

```python
import argparse

parser = argparse.ArgumentParser(description="训练脚本")
parser.add_argument("--lr", type=float, default=1e-3, help="学习率")
parser.add_argument("--batch_size", type=int, default=32)
parser.add_argument("--seed", type=int, default=42)
parser.add_argument("--config", type=str, default="config.yaml")
args = parser.parse_args()

# 命令行使用
# python train.py --lr 0.01 --batch_size 64
```

**配置文件 + 命令行组合**：

```python
# 默认值来自配置文件，命令行可覆盖
config = yaml.safe_load(open(args.config))
config["lr"] = args.lr if args.lr else config["lr"]
```

> **组合用法**：`python train.py --config config.yaml --lr 0.01`——平时改 config.yaml，临时实验用命令行覆盖。

## 随机种子：让"随机"变"确定"

### 为什么深度学习里有随机性

| 来源 | 影响 |
|---|---|
| 权重初始化 | 不同初始值 → 不同结果 |
| 数据打乱顺序 | 训练顺序不同 |
| Dropout 等随机层 | 每次前向不同 |
| GPU 并行 | 浮点累加顺序 |

**不锁种子 → 两次训练结果不同 → 无法判断"是模型变好还是运气变好"。**

### 锁种子的标准代码

```python
import random
import numpy as np
import torch

def set_seed(seed):
    random.seed(seed)                    # Python 随机
    np.random.seed(seed)                 # NumPy 随机
    torch.manual_seed(seed)              # PyTorch CPU
    torch.cuda.manual_seed_all(seed)     # PyTorch GPU
    # 让卷积等算法确定性（稍微变慢）
    torch.backends.cudnn.deterministic = True
    torch.backends.cudnn.benchmark = False

set_seed(42)   # 脚本开头调用一次
```

> **注意**：锁种子只保证"同一台机器、同一环境"可复现。换 GPU 型号/库版本，结果仍可能微变——所以还要记录环境版本（2.1.11 Git/环境锁定）。

## 目录规范：一眼看懂项目结构

```
temperature_anomaly/              ← 项目根
├── data/                         ← 数据（只读，不手工改）
│   ├── raw/                      ← 原始数据
│   └── processed/                ← 预处理后
├── src/                          ← 代码
│   ├── models/                   ← 模型定义
│   ├── data_loader.py
│   └── utils.py
├── configs/                      ← 配置文件
│   ├── baseline.yaml
│   └── exp_001.yaml
├── runs/                         ← 实验输出（每次实验一个目录）
│   └── exp_001/
│       ├── config.yaml           ← 本次实验的配置快照
│       ├── train.log
│       ├── loss_curve.png
│       ├── metrics.json
│       └── model_best.pth
└── README.md
```

**核心原则**：

1. **数据、代码、输出三分**——数据只读、代码不动、输出可删
2. **一次实验一个目录**（runs/exp_001/）——里面放配置快照 + 日志 + 模型
3. **配置快照**：实验开始把 config 复制进 runs 目录——**结果永远能找到对应的配置**

```python
# 实验开始时保存配置快照
import shutil
shutil.copy("config.yaml", f"runs/{exp_name}/config.yaml")
```

## 总结

| 工具 | 一句话 |
|---|---|
| 配置文件 | 参数集中管理，一份配置 = 一次实验的身份证 |
| YAML | 配置的工业标准，可 diff、可让非程序员改 |
| argparse | 命令行覆盖配置，临时实验不改文件 |
| 随机种子 | 锁死初始化/打乱/随机层——让实验可比 |
| 目录规范 | 数据/代码/输出三分，一次实验一个目录 |
| 配置快照 | 实验输出里必有本次配置——结果永远可追溯 |

> 工程规范一句话：**代码不动、配置说话、种子锁死、目录分明**。四个习惯加起来，就把"炼丹玄学"变成"可复现实验"——这是后面所有对照实验（消融、基线对比）可信度的前提。
