## 先看全景：训练循环就 10 行

2.2.1~2.2.4 学的一切，汇合成这段代码：

```python
import torch
import torch.nn as nn
import torch.optim as optim

# ===== 组装（前面四节的内容）=====
model = MyNet()                                  # 2.2.3 模型
train_loader = DataLoader(train_dataset, batch_size=32, shuffle=True)   # 2.2.2 数据
criterion = nn.CrossEntropyLoss()                # 2.2.4 损失
optimizer = optim.AdamW(model.parameters(), lr=1e-3)    # 2.2.4 优化器
scheduler = optim.lr_scheduler.CosineAnnealingLR(optimizer, T_max=epochs)  # 2.2.4 调度器

# ===== 训练循环（核心 5 行）=====
model.train()
for epoch in range(epochs):
    for x, y in train_loader:
        pred = model(x)              # 1. 前向（2.2.3）
        loss = criterion(pred, y)    # 2. 算损失（2.2.4）
        optimizer.zero_grad()        # 3. 清梯度
        loss.backward()              # 4. 反向（2.2.1 自动微分）
        optimizer.step()             # 5. 更新参数
    scheduler.step()                 # 6. 调学习率
```

**六个动作对应前四节**：前向（2.2.3）→ 损失（2.2.4）→ 清梯度 → 反向（2.2.1）→ 更新（2.2.4）→ 调度（2.2.4）。

## 为什么必须 zero_grad：梯度是"累积"的

```python
loss.backward()     # 梯度**累加**到 .grad
```

PyTorch 的梯度是**累加**的——每调一次 backward，`w.grad` 加上新的梯度，不会自动清零。所以：

```python
optimizer.zero_grad()   # 先把 w.grad 清零
loss.backward()         # 再累加本次梯度 → w.grad = 本次梯度
optimizer.step()        # 用这个梯度更新
```

**顺序不能乱**：`zero_grad → backward → step` 是铁律。常见 bug：忘了 zero_grad → 梯度累积越来越大 → 训练发散。

> **zero_grad 的三个等价写法**：`optimizer.zero_grad()`（最常用）、`model.zero_grad()`、手动 `for p in model.parameters(): p.grad.zero_()`。优化器版本最简洁。

## 完整模板：训练 + 验证循环

```python
for epoch in range(epochs):
    # ===== 训练阶段 =====
    model.train()                      # 2.2.3：Dropout 生效
    train_loss = 0.0
    for x, y in train_loader:
        optimizer.zero_grad()
        loss = criterion(model(x), y)
        loss.backward()
        nn.utils.clip_grad_norm_(model.parameters(), max_norm=1.0)   # 梯度裁剪
        optimizer.step()
        train_loss += loss.item()

    # ===== 验证阶段 =====
    model.eval()                       # 2.2.3：Dropout 关、BatchNorm 历史统计
    val_loss = 0.0
    with torch.no_grad():              # 2.2.6：验证不算梯度（省内存）
        for x, y in val_loader:
            val_loss += criterion(model(x), y).item()

    # ===== 调度 =====
    scheduler.step()

    print(f"epoch {epoch}: train {train_loss/len(train_loader):.4f}, val {val_loss/len(val_loader):.4f}")
```

**五个关键点**：
1. **train()/eval() 切换**（2.2.3 的坑）：训练和验证阶段必须分别设置
2. **with torch.no_grad()**：验证不算梯度——省显存且更快（2.2.6 详讲）
3. **梯度裁剪**：防梯度爆炸（见下）
4. **loss.item()**：把 Tensor 变成 Python 数字（否则会累积计算图！）
5. **每 epoch 打印**：train 降、val 不降 = 过拟合信号（1.3.8）

> **与 1.3.8 的连接**：训练损失 ↓ 验证损失 ↑ = 过拟合（高方差）→ 加正则化/数据/早停。训练和验证都不降 = 欠拟合（高偏差）→ 加大模型。

## 梯度裁剪：防止梯度爆炸

**问题**：深层网络反向传播时梯度可能指数级增长（1.2.2 链式法则连乘）→ 一次更新就把参数"踢飞"（loss 变 NaN）。

```python
# 在 backward 之后、step 之前
nn.utils.clip_grad_norm_(model.parameters(), max_norm=1.0)
# 把整个梯度向量的范数限制在 1.0 以内（超了就按比例缩小）
```

**原理**：如果 $\|\nabla\| > \text{max\_norm}$，按 $\text{max\_norm} / \|\nabla\|$ 的比例缩放所有梯度——**方向不变、大小受限**。

| 场景 | 是否需要裁剪 |
|---|---|
| 简单 CNN（ResNet 等） | 通常不需要 |
| RNN/LSTM（时序） | **必须**（1.4.2 讲过循环结构梯度易爆炸） |
| Transformer | 常用（防训练不稳定） |

> **NaN 检查**（2.2.9 详讲）：训练中 loss 变 NaN 的第一嫌疑就是梯度爆炸——先试梯度裁剪或调小学习率。

## 训练循环的常见错误速查

| 错误 | 症状 | 修复 |
|---|---|---|
| 忘了 `zero_grad()` | 损失震荡/发散 | 每步前清零 |
| 忘了 `model.eval()` | 验证结果每次不同 | 验证前切换 |
| 验证没包 `no_grad()` | 显存爆掉/验证慢 | `with torch.no_grad():` |
| `loss.item()` 漏掉 | 显存缓慢增长 | 记录时转 Python 数字 |
| 梯度爆炸 | loss 变 NaN | 梯度裁剪/调小 lr |
| 调度器位置错 | 学习率没生效 | 每个 epoch 后 `scheduler.step()` |

## 总结

| 概念 | 一句话 |
|---|---|
| 训练循环 6 动作 | 前向→损失→清梯度→反向→更新→调度 |
| zero_grad | 梯度是累积的，每步必须先清零（顺序是铁律） |
| train()/eval() | 训练/验证阶段必须切换（2.2.3） |
| no_grad() | 验证不算梯度，省显存（2.2.6 详讲） |
| 梯度裁剪 | 梯度范数超限就按比例缩小——RNN/Transformer 必须 |
| 过拟合信号 | train ↓ val ↑ → 高方差（1.3.8） |
