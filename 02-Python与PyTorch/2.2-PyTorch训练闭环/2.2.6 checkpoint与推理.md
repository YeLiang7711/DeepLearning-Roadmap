**本节内容**：训练成果怎么保存和恢复——checkpoint（检查点）的三要素、断点续训、推理模式与 ONNX 导出。

> 属于：[[0-概述-PyTorch训练闭环|PyTorch 训练闭环]] > 2.2.6
> 掌握程度：**深入** — 训练与部署的分界线

> **术语**：checkpoint（检查点）= 训练中保存的模型状态快照；state_dict（状态字典）= 参数名→张量的字典；断点续训 = 从保存的 checkpoint 继续训练；推理（inference）= 用训练好的模型做预测；ONNX = 跨框架模型格式。

---

## 为什么需要 checkpoint

训练 100 个 epoch 要跑几天。**中途断电/报错/换机器 → 全部重来**？checkpoint 就是"存档点"——随时保存、随时恢复。

另外：**保存的必须是模型，不只是代码**——训练完的权重才是成果（2.2.4 说过 AdamW 的 lr 等超参也在优化器里）。

---

## state_dict：PyTorch 保存的核心格式

```python
# 模型参数：名字 → 张量 的字典（2.2.3 讲过）
model.state_dict()
# {'fc1.weight': tensor(...), 'fc1.bias': tensor(...), ...}
```

**为什么用 state_dict 而不是整个 model**：只存张量（紧凑、跨版本兼容），不存代码结构（结构由代码定义）。

```python
# 保存
torch.save(model.state_dict(), "model.pth")

# 加载（必须先有同样结构的模型）
model = MyNet()
model.load_state_dict(torch.load("model.pth", weights_only=True))
# ↑ weights_only=True：只允许加载张量和简单数据
#   恶意 .pth 文件可能通过反序列化执行任意代码（安全实践，默认应开启）
```

> **与 2.2.3 的连接**：`state_dict()` 是 2.2.3 讲过的"名字→张量字典"——保存/加载就是把它写进文件再读回来。

---

## 完整 checkpoint：模型 + 优化器 + epoch + 最佳指标

只存模型不够——**断点续训需要优化器状态**（Adam 的动量/自适应步长，2.2.4）。完整 checkpoint 保存四样：

```python
# 保存（每个 epoch 后或达到最佳时）
torch.save({
    "epoch": epoch,                    # 1. 训练到哪了
    "model_state": model.state_dict(), # 2. 模型参数
    "optimizer_state": optimizer.state_dict(),  # 3. 优化器状态（续训必需）
    "best_val_loss": best_val_loss,    # 4. 最佳指标（选模型用）
}, f"checkpoints/epoch_{epoch}.pth")

# 恢复（断点续训）
checkpoint = torch.load("checkpoints/epoch_50.pth", weights_only=True)
model.load_state_dict(checkpoint["model_state"])
optimizer.load_state_dict(checkpoint["optimizer_state"])
start_epoch = checkpoint["epoch"] + 1   # 从保存处继续
best_val_loss = checkpoint["best_val_loss"]
```

**为什么 optimizer_state 必须存**：Adam 的 $m_t$（动量）和 $v_t$（步长估计）是训练历史——不存的话续训等于"失忆重启"，前几十个 epoch 白跑了（1.4.2 讲过）。

**最佳模型策略**（工业标准）：

```python
# 每个 epoch 后：验证集变好才覆盖保存
if val_loss < best_val_loss:
    best_val_loss = val_loss
    torch.save({"model_state": model.state_dict(), ...}, "best_model.pth")
    # 同时把"当前 epoch 检查点"也存一份（防中断）
```

> **与 2.1.10 的连接**：checkpoint 存进 `runs/exp_001/`（2.1.10 的目录规范）——每个实验目录里有"配置快照 + 日志 + 模型"，可复现性闭环。

## 推理模式：模型上线怎么用

```python
# ===== 训练结束，进入推理 =====
model.eval()                    # 关 Dropout（2.2.3）
with torch.no_grad():           # 关梯度：省显存、速度快
    logits = model(x_test)      # 输出 logits（原始分数）
    probs = torch.softmax(logits, dim=1)   # 转概率（分类用）
    pred = probs.argmax(dim=1)  # 取最大概率类别
```

**为什么推理要 no_grad**：
- 不构建计算图 → **显存占用大幅下降**（只存前向结果）
- 速度快（跳过反向传播的准备）

| 模式 | 梯度 | 用途 |
|---|---|---|
| `model.train()` | 要（backward 用） | 训练 |
| `model.eval()` + `no_grad()` | 不要 | 验证/测试/推理 |

> **与 1.3.5 的连接**：推理输出 `probs` 就是"模型给每个类别的概率"——阈值判定（分类置信度）和异常检测分数都从这里来。

## ONNX 导出：跨框架部署

PyTorch 模型要部署到别的环境（C++、TensorRT、移动端），导出为标准格式 ONNX：

```python
# 导出
dummy = torch.randn(1, 1, 64, 64)       # 与真实输入同 shape
torch.onnx.export(model, dummy, "model.onnx",
                  input_names=["input"], output_names=["output"],
                  dynamic_axes={"input": {0: "batch"}, "output": {0: "batch"}})

# 验证（关键！导出后必须验证输出一致）
import onnxruntime as ort
ort_session = ort.InferenceSession("model.onnx")
onnx_out = ort_session.run(None, {"input": dummy.numpy()})[0]
torch_out = model(dummy).detach().numpy()
print(np.allclose(onnx_out, torch_out, atol=1e-5))   # True = 一致
```

> **与 30 章部署的连接**：完整部署流程（TensorRT、前后处理一致性、版本管理）在 17-模型压缩与部署 展开。这里记住两件事：**ONNX 导出后必须数值验证**、**部署端前后处理和训练端必须完全一致**（工业故障常来自管线差异）。

## 总结

| 概念 | 一句话 |
|---|---|
| state_dict | 参数名→张量字典，保存/加载的核心格式 |
| 完整 checkpoint | 模型 + 优化器 + epoch + 最佳指标（四件套） |
| 断点续训 | load 四件套 + 从保存的 epoch 继续 |
| optimizer_state | Adam 的动量/步长历史——不存 = 失忆重启 |
| 最佳模型 | 验证集变好才覆盖（选模型标准） |
| 推理模式 | eval() + no_grad()——关随机、关梯度 |
| ONNX | 跨框架部署格式——导出后必须数值验证 |

> checkpoint 一句话：**训练是耗时的，成果要能救回来**——四件套保存让你断电可续、变好才留；推理模式让模型从"训练态"变"部署态"。
