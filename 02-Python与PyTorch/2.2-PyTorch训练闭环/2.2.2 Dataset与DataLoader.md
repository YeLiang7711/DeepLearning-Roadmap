**本节内容**：数据怎么喂给模型——Dataset（数据集）定义"数据长什么样"，DataLoader（数据加载器）负责"批量、打乱、并行加载"。

> 属于：[[0-概述-PyTorch训练闭环|PyTorch 训练闭环]] > 2.2.2
> 掌握程度：**深入** — 数据管线的核心

> **术语**：Dataset = 数据集类；DataLoader = 数据加载器；batch（批次）= 一次喂给模型的样本组；epoch（轮次）= 完整遍历一遍训练集；shuffle（打乱）= 每轮重新随机排序；Sampler（采样器）= 决定取样本顺序的组件。

---

## 先看一个例子：1000 张温度图怎么训练

你有 1000 张温度图，每张配一个标签（正常/异常）。训练时不能：

- ❌ 全部一次加载进内存——1000 张 × 64×64 × 4 字节 ≈ 16MB，但真实数据集是 GB 级
- ❌ 每次只取一张——GPU 要批量并行（2.1.3 讲过批处理）
- ❌ 顺序固定——模型会记住顺序（过拟合数据排列）

**PyTorch 的答案：Dataset 管"怎么取一张"，DataLoader 管"怎么批量、打乱、并行取"。**

---

## Dataset：定义"数据长什么样"

只需实现两个魔术方法（2.1.2 讲过）：

```python
from torch.utils.data import Dataset

class TemperatureDataset(Dataset):
    """温度图数据集：返回 (图像, 标签) 对"""

    def __init__(self, paths, labels):
        self.paths = paths          # 路径列表（不加载图像！）
        self.labels = labels

    def __len__(self):
        """len(dataset) → 样本总数"""
        return len(self.paths)

    def __getitem__(self, idx):
        """dataset[i] → 第 i 个样本，这里才真正读数据"""
        img = load_temperature(self.paths[idx])   # 按需加载（省内存）
        label = self.labels[idx]
        return img, label

# 使用
dataset = TemperatureDataset(paths, labels)
len(dataset)          # 1000
img, label = dataset[0]   # 取第一张
```

**关键设计**：
- `__init__` 只存路径**不加载数据**——内存只占路径列表
- `__getitem__` 才真正读——用到才加载（2.1.3 的惰性思想）

> **与 2.1.2 的连接**：这就是 SimpleDataset 的正式版——PyTorch 的 Dataset 就是要求你实现 `__len__` 和 `__getitem__` 这两个魔术方法。

## DataLoader：批量、打乱、并行

```python
from torch.utils.data import DataLoader

dataloader = DataLoader(
    dataset,
    batch_size=32,        # 每批 32 张（2.1.3 的 Mini-batch）
    shuffle=True,         # 每个 epoch 打乱顺序
    num_workers=4,        # 4 个进程并行预加载下一批
)

for batch in dataloader:              # 每轮循环取一个 batch
    images, labels = batch             # images: (32, 1, 64, 64)
    # 训练...
```

### DataLoader 做了什么（拆开看）

```
dataset[0], dataset[1], ..., dataset[31]    ← 按索引取 32 张
        ↓ 自动堆叠（collate，见下）
batch = (images(32,1,64,64), labels(32,))
        ↓
把这一批交给模型 → 训练（2.2.5）
```

| 参数 | 作用 | 典型值 |
|---|---|---|
| `batch_size` | 每批样本数 | 32/64/128（看显存，2.2.7） |
| `shuffle` | 每个 epoch 重新打乱 | 训练 True、验证 False |
| `num_workers` | 并行预加载进程数 | 4~8（0 = 不并行） |
| `drop_last` | 最后不足一批时丢弃 | 训练常 True（稳定 batch 大小） |

> **为什么 shuffle**：模型会记住训练顺序（1.3.8 的过拟合）。打乱后每个 epoch 看到的顺序不同，防止学到"第 i 张后面是第 i+1 张"这种排列规律。**验证集不 shuffle**——评估要稳定可复现。

## Sampler：定制取样本的顺序

DataLoader 默认顺序取/随机取，需要特殊策略时用 Sampler：

```python
from torch.utils.data import WeightedRandomSampler

# 场景：类别不平衡（900 正常 vs 100 异常）
# 给少数类更高的采样权重 → 每个 epoch 两类都见到
weights = [1.0 if label == 0 else 9.0 for label in labels]
sampler = WeightedRandomSampler(weights, num_samples=len(labels), replacement=True)

dataloader = DataLoader(dataset, batch_size=32, sampler=sampler)
# 用了 sampler 就不能用 shuffle（两者互斥）
```

| Sampler | 用途 |
|---|---|
| SequentialSampler | 按顺序（默认） |
| RandomSampler | 随机（shuffle=True 的内部实现） |
| **WeightedRandomSampler** | 类别不平衡时给少数类加权 |
| SubsetRandomSampler | 只取子集（划分训练/验证） |

> **类别不平衡**（路线图 6 章：分类）是工业数据的常态——加权采样是最简单的应对之一（另一个是 Focal 损失，03 章讲）。

## collate_fn：怎么把样本"合成"一批

默认行为：把样本堆叠成张量（要求所有样本 shape 相同）。样本形状不同时需要自定义：

```python
def my_collate(batch):
    images, labels = zip(*batch)
    images = torch.stack(images)     # (B, C, H, W)
    return images, torch.tensor(labels)

dataloader = DataLoader(dataset, batch_size=32, collate_fn=my_collate)
```

**典型场景**：
- 变长序列（NLP：每句长度不同 → padding 到 batch 内最长）
- 图片尺寸不同（先 resize 或 padding）
- 返回值不止 (图像, 标签)（比如还要返回路径）

> **与 2.1.3 的连接**：DataLoader 本身就是一个**迭代器**——`for batch in dataloader` 每轮从开头重新开始，内部用生成器/多进程按需生产，内存里永远只有一批。

## 总结

| 概念 | 一句话 |
|---|---|
| Dataset | 定义"怎么取一张"（__len__/__getitem__），只存路径不加载 |
| DataLoader | 批量 + 打乱 + 并行加载的调度器 |
| batch_size | 每批样本数（GPU 并行度，2.2.7 看显存） |
| shuffle | 每轮打乱——防模型记住顺序（验证集不打乱） |
| Sampler | 定制取序（加权采样解决类别不平衡） |
| collate_fn | 样本形状不同时自定义"合成一批" |
| 惰性加载 | 用到才读——大数据集内存可控（2.1.3） |

> Dataset + DataLoader 一句话：**Dataset 回答"一张图怎么取"，DataLoader 回答"一批图怎么高效取"**。训练代码永远长这样：`for batch in dataloader`——数据管线就绪，接下来就是模型的事了（2.2.3）。
