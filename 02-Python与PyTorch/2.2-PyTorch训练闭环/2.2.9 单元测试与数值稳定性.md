**本节内容**：让训练代码可靠——shape 断言、梯度检查、数值稳定性测试，以及"最小过拟合测试"的调试方法论。

> 属于：[[0-概述-PyTorch训练闭环|PyTorch 训练闭环]] > 2.2.9
> 掌握程度：**会用** — 从"能跑"到"可信"

> **术语**：单元测试（unit test）= 对单个函数/模块的自动化验证；shape 测试 = 验证张量形状；梯度检查（gradient check）= 用数值微分验证自动梯度正确性；NaN = Not a Number，非法数值。

---

## 为什么需要测试：训练代码的"便宜的错误最贵"

训练跑 100 个 epoch 才发现 bug → 白跑几天。**测试在训练前把 bug 找出来**（2.1.10 工程规范的延续）。

训练代码最常见的错误：
- shape 不对（2.2.1 三大属性）
- 梯度没流动（模型没学）
- 数值不稳定（NaN）
- 数据泄漏（1.3.8 的坑）

---

## 1. Shape 测试：每个模块验证输入输出

```python
def test_model_shapes():
    model = MyNet()
    x = torch.randn(4, 1, 64, 64)        # batch=4, 单通道 64×64

    out = model(x)
    assert out.shape == (4, 2), f"输出 shape 错误: {out.shape}"

    # 边界情况：batch=1（推理常见）
    out1 = model(torch.randn(1, 1, 64, 64))
    assert out1.shape == (1, 2)

    # 极端尺寸
    out_small = model(torch.randn(4, 1, 32, 32))
    assert out_small.shape == (4, 2)

    print("✅ shape 测试通过")
```

> **与 2.2.1 的连接**：shape 是调试第一检查项——测试就是把"检查 shape"自动化。**模型写完先跑 shape 测试**，比训练时爆错快 100 倍。

## 2. 梯度检查：验证梯度真的在流动

```python
def test_gradients_flow():
    model = MyNet()
    x = torch.randn(4, 1, 64, 64, requires_grad=True)

    loss = model(x).sum()     # 随便一个标量损失
    loss.backward()

    # 所有参数都有梯度且非零
    for name, param in model.named_parameters():
        assert param.grad is not None, f"{name} 没有梯度！"
        assert param.grad.abs().sum() > 0, f"{name} 梯度为零（层死了）"

    # 输入也有梯度
    assert x.grad is not None
    print("✅ 梯度流测试通过")
```

**发现的问题**：
- `param.grad is None` → 该层没参与计算（forward 漏了）
- 梯度全零 → ReLU 死亡（1.2.4 讲过）或数值问题

**梯度检查（数值微分验证）**：用解析梯度 vs 数值梯度对比：

```python
def test_gradient_correctness():
    x = torch.randn(5, requires_grad=True)
    y = (x ** 2).sum()

    y.backward()
    analytical = x.grad          # 自动微分结果

    # 数值微分：f(x+ε) - f(x-ε) / 2ε
    eps = 1e-6
    numeric = (torch.sum((x + eps) ** 2) - torch.sum((x - eps) ** 2)) / (2 * eps)
    assert torch.allclose(analytical, numeric, atol=1e-4), "梯度计算错误"
    print("✅ 梯度正确性通过")
```

> **与 1.2.1 的连接**：数值微分就是导数的定义（Δx 无限小的极限）——用定义验证自动微分（1.2.2 反向传播）算得对不对。PyTorch 的 `torch.autograd.gradcheck` 做了同样的事。

## 3. 数值稳定性测试：NaN 与 Inf

```python
def test_numerical_stability():
    model = MyNet()
    model.eval()

    # 大数值输入（防溢出）
    x = torch.randn(4, 1, 64, 64) * 1000
    out = model(x)
    assert torch.isfinite(out).all(), "大输入导致 NaN/Inf"

    # 极端输入（全零、全一）
    for extreme in [torch.zeros(4, 1, 64, 64), torch.ones(4, 1, 64, 64)]:
        out = model(extreme)
        assert torch.isfinite(out).all()

    # Softmax/LogSoftmax 稳定性（1.2.4 的 logits 用法）
    logits = torch.randn(4, 1000) * 100     # 极端 logits
    probs = torch.softmax(logits, dim=1)
    assert torch.isfinite(probs).all() and (probs.sum(dim=1) - 1).abs().max() < 1e-5
    print("✅ 数值稳定性通过")
```

**NaN 的来源排查顺序**（训练中 loss 变 NaN）：
1. 梯度爆炸（1.2.2 链式连乘）→ 梯度裁剪/调小 lr（2.2.5）
2. log(0) 或 0/0 → 检查损失输入（加 epsilon）
3. 初始化不当 → Xavier/Kaiming（4 章）
4. 学习率过大 → 减 lr

> **与 1.3.5 的连接**：数值稳定性不是"洁癖"——NaN 会污染整条训练曲线，让指标完全不可信。

## 4. 最小过拟合测试：调试模型的黄金方法

**核心方法**：让模型拟合**极小数据**（8~16 个样本）——如果连这么少的数据都拟合不了，说明代码有 bug；拟合了，说明代码基本正确。

```python
def test_minimal_overfit():
    model = MyNet()
    optimizer = optim.AdamW(model.parameters(), lr=1e-3)
    criterion = nn.CrossEntropyLoss()

    # 只取 8 个样本
    x = torch.randn(8, 1, 64, 64)
    y = torch.randint(0, 2, (8,))

    # 训练几百步
    for _ in range(500):
        optimizer.zero_grad()
        loss = criterion(model(x), y)
        loss.backward()
        optimizer.step()

    acc = (model(x).argmax(1) == y).float().mean().item()
    assert loss.item() < 0.1 and acc == 1.0, \
        f"8 个样本都过拟合不了: loss={loss.item():.4f}, acc={acc}"
    print(f"✅ 最小过拟合通过（loss={loss.item():.4f}）")
```

**为什么有效**：8 个样本没有任何"泛化"要求——模型记忆能力足够强，**学不会 = 代码有 bug**（数据/模型/损失/优化器某一环坏了）。

> **与 1.3.8 的连接**：过拟合在正常训练里是问题，在这里是**测试工具**——"能过拟合小数据"证明管线通，之后再谈泛化。

## 完整测试组织（pytest）

```python
# test_model.py —— 用 pytest 运行：pytest test_model.py
def test_shapes(): ...
def test_gradients(): ...
def test_stability(): ...
def test_minimal_overfit(): ...

# 训练前的"冒烟测试"（smoke test）：跑一遍最小流程
def test_smoke():
    """10 秒内跑完一个小训练流程，确认全链路通"""
    model, loader, optimizer = build_pipeline(batch_size=4, epochs=1)
    for x, y in loader:
        optimizer.zero_grad()
        loss = criterion(model(x), y)
        loss.backward()
        optimizer.step()
    assert torch.isfinite(loss)
```

**建议的测试时机**：
- 写模型后 → shape + 梯度测试
- 改数据管线后 → 冒烟测试
- 每个实验前 → 最小过拟合测试

## 总结

| 测试 | 找什么 bug | 什么时候跑 |
|---|---|---|
| Shape 测试 | 维度不匹配 | 写完模型 |
| 梯度测试 | 梯度不流动/层死了 | 写完模型 |
| 数值稳定性 | NaN/Inf/溢出 | 大输入或换损失后 |
| **最小过拟合** | 管线整体 bug | **每个实验前** |
| 冒烟测试 | 全链路不通 | 改代码后 |

> 测试一句话：**训练前的 5 分钟测试，省训练后的 5 小时排查**——shape、梯度、NaN、最小过拟合四个测试，把训练代码从"能跑"变成"可信"。
