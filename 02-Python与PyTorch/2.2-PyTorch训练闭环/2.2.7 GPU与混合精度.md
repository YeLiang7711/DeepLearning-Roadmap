**本节内容**：让训练跑得快、显存省——GPU 的 .cuda()/.to() 用法、显存监控与优化、混合精度（AMP）训练。

> 属于：[[0-概述-PyTorch训练闭环|PyTorch 训练闭环]] > 2.2.7
> 掌握程度：**会用** — 训练效率的关键

> **术语**：GPU（图形处理器）= 并行计算硬件；device（设备）= 计算在哪发生（cpu/cuda）；AMP（Automatic Mixed Precision，自动混合精度）= 用 FP16 算、FP32 存；显存（VRAM）= GPU 的专用内存。

---

## 为什么用 GPU：并行计算的威力

| | CPU | GPU |
|---|---|---|
| 核心数 | 8~16 个 | 数千个 |
| 适合 | 串行、逻辑控制 | **并行矩阵运算** |
| 训练速度 | 基准 | 快 10~50 倍 |

深度学习的计算是矩阵乘法（1.1.1 的全连接、2.2.1 的 Tensor 运算）——**天生适合 GPU 并行**。PyTorch 一行代码把计算挪到 GPU：

```python
# 判断 GPU 是否可用
print(torch.cuda.is_available())   # True/False

# 三种写法（等价）
model.cuda()               # 旧写法
model.to("cuda")           # 推荐写法
model.to("cuda:0")         # 指定第 0 块 GPU
```

## device 一致性：最常见的 GPU 报错

**CPU 张量和 GPU 张量不能直接运算**——报错 "Expected all tensors to be on the same device"：

```python
device = "cuda" if torch.cuda.is_available() else "cpu"

# 模型和数据都要搬到同一 device
model = MyNet().to(device)
x = x.to(device)          # 每个 batch 都搬
y = y.to(device)

# 训练循环里
for x, y in train_loader:
    x, y = x.to(device), y.to(device)   # 数据搬到 GPU
    ...
```

**规则**：**模型、数据、标签必须在同一个 device**。数据搬运在每个 batch 循环里做（`x.to(device)` 很便宜）。

> **与 2.2.1 的连接**：dtype/shape/device 是 Tensor 三大属性——device 报错时先查这三样。

## 显存监控与优化

**显存不足（CUDA out of memory）** 是训练最常遇到的硬件报错：

```python
# 监控当前显存占用
print(torch.cuda.memory_allocated() / 1024**3, "GB")   # 已用
print(torch.cuda.memory_reserved() / 1024**3, "GB")    # 已预留

# 清空缓存（重新分配时用）
torch.cuda.empty_cache()
```

**显存去哪了**（按占用排序）：

| 占用 | 原因 | 对策 |
|---|---|---|
| 1️⃣ | **计算图**（前向中间结果） | 验证用 `no_grad()`、减小 batch |
| 2️⃣ | 输入数据 | `x.to(device)` 用后即弃 |
| 3️⃣ | 参数 + 优化器状态 | Adam 额外存两份状态（2.2.4） |
| 4️⃣ | 梯度 | 必存 |

**显存不够时的第一调整顺序**：`batch_size` 减半 → `no_grad()` 检查 → 混合精度（下节）→ 梯度累积。

> **梯度累积**：显存不够但想要大 batch 的折中——小 batch 累加梯度再更新（batch_size=32 × 4 步 = 等效 128），代价是 BatchNorm 统计仍按小 batch。

---

## 混合精度（AMP）：又快又省显存

### 核心思想

**FP32（32 位）→ FP16（16 位）**：一半显存、近乎两倍速度。但**直接全用 FP16 会精度崩**（梯度下溢、数值不稳）。

**AMP 的做法：** 能省则省——**前向和反向用 FP16（快），但"关键地方"保留 FP32**（梯度主权重、损失计算）。

```python
from torch.cuda.amp import autocast, GradScaler

scaler = GradScaler()   # 梯度缩放器：防 FP16 梯度下溢

model = MyNet().cuda()
optimizer = optim.AdamW(model.parameters(), lr=1e-3)

for x, y in train_loader:
    x, y = x.cuda(), y.cuda()
    optimizer.zero_grad()

    with autocast():                    # 自动混合精度上下文
        loss = criterion(model(x), y)

    scaler.scale(loss).backward()       # 缩放梯度（防下溢）
    scaler.step(optimizer)              # 先反缩放再更新
    scaler.update()                     # 调整缩放因子
```

### 四个 AMP API 对应什么

| API | 作用 |
|---|---|
| `autocast()` | 上下文：内部运算自动用 FP16 |
| `GradScaler()` | 管理梯度缩放（防止 FP16 小梯度变 0） |
| `scaler.scale(loss)` | 损失放大后再反向 |
| `scaler.step(optimizer)` | 反缩放后更新参数 |

> **与 2.2.5 的连接**：这是 2.2.5 训练循环的"GPU 加速版"——动作顺序不变，只是包了 autocast 和 scaler。

## 训练循环的 GPU 完整版

```python
device = "cuda" if torch.cuda.is_available() else "cpu"
model = MyNet().to(device)
optimizer = optim.AdamW(model.parameters(), lr=1e-3)
scaler = GradScaler()

for epoch in range(epochs):
    model.train()
    for x, y in train_loader:
        x, y = x.to(device), y.to(device)
        optimizer.zero_grad()
        with autocast():
            loss = criterion(model(x), y)
        scaler.scale(loss).backward()
        scaler.step(optimizer)
        scaler.update()
    # 验证：不需要 scaler
    model.eval()
    with torch.no_grad():
        for x, y in val_loader:
            x, y = x.to(device), y.to(device)
            val_loss += criterion(model(x), y).item()
```

**要点**：
- 训练用 `scaler` 三步（scale→step→update）
- **验证不需要 scaler**（没有梯度缩放的必要）
- 数据每步 `to(device)`

## 总结

| 概念 | 一句话 |
|---|---|
| GPU 加速 | 矩阵并行——快 10~50 倍 |
| device 一致性 | 模型/数据/标签同 device（最常见报错） |
| 显存优化 | 先减 batch → no_grad → AMP → 梯度累积 |
| AMP | FP16 算 + FP32 保精度——一半显存、近两倍速度 |
| GradScaler | 防 FP16 梯度下溢（必须配合） |
| GPU 训练循环 | autocast + scaler 三步替换普通 backward/step |

> GPU 一句话：**`.to(device)` 搬家、`no_grad()` 省显存、AMP 加速**——三个动作让训练从"能跑"变"跑得快"。
